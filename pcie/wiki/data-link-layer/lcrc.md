# LCRC（Link CRC，链路层循环冗余校验）

**LCRC（Link CRC）** 是 PCIe 数据链路层为每个 TLP（Transaction Layer Packet）强制附加的 **32 位校验码**。它就像贴在包裹外层的"防篡改封条"：每经过一条 PCIe 链路，接收端都要重新计算校验，一旦发现哪怕 1 个比特在传输中翻转，就立即丢弃该包并回复 `Nak` 请求重传。

> **直观类比**：如果把跨越多个中转站（Switch）的 PCIe 通信比作跨省快递，**LCRC** 就是"每一段运输车队交接时贴的封条"——只管这一段路有没有颠坏（逐跳校验、损坏立即重发）；而事务层可选的 **ECRC** 则是"发货方贴在最内层货箱上的原厂封条"，直到最终收货方才拆封核对（端到端校验）。

---

## 1. LCRC 在 TLP 帧中的位置与覆盖范围

数据链路层在从事务层拿到 TLP 后，会在头部加上 12 位序列号（与 4 位保留位组成 2 字节），并在尾部附上 4 字节（32 位）LCRC：

```
┌──────────┬──────────────────┬─────────────────┬──────────────┬───────────┬──────────┐
│   STP    │  Seq# (12 bits)  │   TLP Header    │ Data Payload │   ECRC    │   LCRC   │
│ (物理层) │  + Rsvd (4 bits) │   (3 或 4 DW)   │ (0~1024 DW)  │ (可选 1DW)│ (32-bit) │
└──────────┴──────────────────┴─────────────────┴──────────────┴───────────┴──────────┘
           ├──────────────────┴─────────────────┴──────────────┴───────────┤
           │◄─────────────── LCRC 计算覆盖范围 ───────────────────────────►│
```

> **重要细节**：
> - **包含在内**：`Sequence Number`（含 4 位保留位）、完整的 `TLP Header`、`Data Payload`（若有）以及可选的 `ECRC`（TLP Digest）。
> - **不包含在内**：物理层帧定界符（`STP`/`END`）以及 `LCRC` 字段本身。
> - **逐跳重算**：Switch 在转发 TLP 时会剥离并验证入向链路的 `Seq#` 与 `LCRC`，在出向链路重新分配新的 `Seq#` 并重新计算 `LCRC`。

---

## 2. 算法特性与检错能力

LCRC 采用标准的 **IEEE 802.3 CRC-32** 多项式（`0x04C11DB7`，初始值 `0xFFFFFFFF`）。由于 TLP 长度通常在 12 字节 ~ 4 KB 之间，LCRC 提供极强的硬件级检错能力：

| 错误类型 | 检测能力 |
|----------|----------|
| 单比特、双比特及任意奇数个比特错误 | **100%** 检测 |
| 长度 ≤ 32 比特的连续突发错误（Burst Error） | **100%** 检测 |
| 长度 > 32 比特的突发错误或随机多比特错误 | **99.9999998%** 检测（漏检率 $\approx 2^{-32}$） |

在硬件实现上（如 Gen 3/4/5 高速控制器），LCRC 并非按位串行计算，而是采用**并行 CRC 矩阵乘法**在单个或极少数时钟周期内流水线完成，几乎不增加额外传输延迟。

## 3. LCRC 校验与错误处理流程

```
物理层解码得到 TLP 帧
        │
        ▼
提取 Sequence Number 与 32-bit LCRC
        │
        ▼
硬件并行计算 (Seq# + TLP Header + Data + [ECRC]) 的 CRC-32
        │
        ├── 校验通过，且 Seq# 连续 ──▶ 送入事务层，并适时回发 Ack DLLP
        │
        ├── 校验通过，但 Seq# 重复 ──▶ 静默丢弃重复包，回发 Ack DLLP（对端可能丢了 Ack）
        │
        └── 校验失败（LCRC 不匹配）──▶ 立即丢弃该 TLP！
                                       记录 AER Correctable Error (BadTLP)
                                       发送 Nak DLLP 通知发送方从上一个正确包后重传
```

## 4. LCRC vs ECRC 核心对比

| 对比维度 | LCRC (Link CRC) | ECRC (End-to-End CRC) |
|----------|-----------------|----------------------|
| **所属协议层** | 数据链路层（Data Link Layer） | 事务层（Transaction Layer） |
| **是否强制** | **强制**（所有 TLP 必须携带） | **可选**（需通过 AER 能力寄存器协商开启） |
| **保护范围** | **逐跳**（仅覆盖相邻两个端口之间的链路） | **端到端**（从 Requester 到 Completer，穿越 Switch） |
| **Switch 行为** | 剥离旧 LCRC、校验后按新 `Seq#` 重算 | 透传不修改（路由字段除外，计算时按规则掩码处理） |
| **出错后果** | 触发硬件自动重传（`Nak`），对软件透明 | 无法靠链路重传修复，上报软件级错误（AER Uncorrectable） |
| **使用场景** | 所有 PCIe 通信 | 高可靠性存储、服务器关键路径（防范 Switch 内部缓存比特翻转） |

## 5. 性能开销与实战监控

- **带宽开销**：固定 4 字节。对于最小 12 字节读请求 TLP，开销占比为 $4 / (2 + 12 + 4) \approx 22\%$；对于常见 256 字节写数据 TLP，开销仅约 **1.5%**；对于 4 KB 大包则不足 **0.1%**。
- **Linux 监控**：LCRC 校验失败会在设备 AER 寄存器中累加 `BadTLP`（可纠正错误），可通过以下命令排查链路信号质量：

```bash
# 查看设备 AER 可纠正/不可纠正错误状态
lspci -vvv -s 01:00.0 | grep -A 4 "CESta:"
# 若 BadTLP 持续增长，说明物理链路存在信号衰减、接触不良或电磁干扰
```

## 6. 关联与引申概念

- **ACK/NAK 协议**：LCRC 校验成功或失败后，接收方正是通过 `Ack` / `Nak` DLLP 通知发送方释放或重传，详见 [ACK/NAK 协议详解](ack-nak.md)。
- **ECRC（End-to-End CRC）**：事务层可选的 32 位端到端校验，弥补 LCRC 无法检测 Switch 内部存储/转发损坏的盲区，详见 [ECRC 详解](../transaction-layer/ecrc.md)。
- **AER（Advanced Error Reporting）**：PCIe 扩展配置空间中的错误报告机制，控制 ECRC 的使能并记录 `BadTLP`、`BadDLLP` 等错误状态。
- **CRC-16（DLLP 校验）**：与 TLP 使用 32 位 LCRC 不同，6 字节的 DLLP 控制包使用 16 位 CRC 进行完整性校验，详见 [DLLP 格式详解](dllp-format.md)。

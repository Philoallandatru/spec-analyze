# PCIe 链路宽度

**一句话总结**：链路宽度（Link Width）指一条 PCIe 链路同时捆绑使用的物理通道（**Lane**）数量，范围从 `x1` 到 `x16`；带宽与宽度成正比，链路训练时会自动协商双方共同支持的最大宽度。

> **直观类比**：如果说 PCIe 代际速率（Gen3/Gen4/Gen5）决定了“每条车道的限速”，那么链路宽度（x1/x4/x16）就是“高速公路的车道数量”。一条 16 车道的高速公路（x16），运力天然是单车道（x1）的 16 倍。

---

## 标准链路宽度与典型应用

每条 **Lane** 由 4 根铜线（1 对发送差分线 `TX+/TX-` + 1 对接收差分线 `RX+/RX-`）组成。PCIe 规范支持以下标准宽度：

| 宽度 | Lane 数 | 物理差分线总数 | 典型设备与插槽 | Gen4 单向理论带宽 |
|------|--------|--------------|---------------|------------------|
| **x1** | 1 | 4 根 | 声卡、Wi-Fi 网卡、USB 扩展卡 | ~1.97 GB/s |
| **x2** | 2 | 8 根 | 部分低功耗 M.2 SSD、嵌入式设备 | ~3.94 GB/s |
| **x4** | 4 | 16 根 | **NVMe SSD (M.2 / U.2)**、10GbE 网卡 | ~7.88 GB/s |
| **x8** | 8 | 32 根 | 25G/100GbE 网卡、RAID 卡、HBA | ~15.75 GB/s |
| **x16** | 16 | 64 根 | **独立显卡 (GPU)**、AI 加速卡 | ~31.50 GB/s |

*(注：规范曾定义过 `x12` 和 `x32`，但极少使用或已在实际产品中被废弃。)*

## 宽度协商与链路拆分（Bifurcation）

### 1. 自动协商规则
链路训练进入 `LTSSM Configuration` 状态时，两端设备通过 `TS1/TS2` 有序集清点物理连通且信号质量达标的 Lane，并按以下规则确定最终宽度：
$$\text{协商宽度} = \min(\text{发送端支持宽度}, \text{接收端支持宽度}, \text{物理连通的可用 Lane 数})$$
且结果必须向下取整为标准宽度（`x16 → x8 → x4 → x2 → x1`）。例如，即便有 12 条 Lane 连通但设备不支持 `x12`，链路也会自动退化为 `x8`。

### 2. 链路拆分（PCIe Bifurcation）
主板或服务器常在 BIOS 中支持 **Bifurcation**，即将 CPU 引出的 1 条 `x16` 链路逻辑拆分为 `x8 + x8` 或 `x4 + x4 + x4 + x4`，用于通过转接卡同时挂载 4 块 NVMe SSD。

## 物理槽位兼容性

PCIe 插槽遵循**“向下兼容、小卡可插大槽”**的机械与电气原则：
- `x1`、`x4`、`x8` 扩展卡可以毫无障碍地插入 `x16` 物理插槽并正常工作（仅使用前几条 Lane）。
- **开放式插槽（Open-Ended Slot）**：部分主板将 `x4` 或 `x8` 插槽末端开口，允许物理长度更大的 `x16` 卡插入，但电气上仍只能以插槽的 `x4` 或 `x8` 宽度运行。

---

## 宽度降级（Width Degradation）与动态省电

### 1. 异常宽度降级
如果一张 `x16` 显卡实际只协商到了 `x4` 或 `x8`，带宽会直接腰斩甚至降至 1/4。常见原因包括：
- **物理接触不良**：金手指氧化、未插紧或 M.2 螺丝歪斜导致部分 Lane 断路。
- **信号完整性恶化**：主板走线损伤或延长线（Riser Cable）质量差，部分 Lane 在训练阶段无法锁定。
- **平台限制**：主板第二条 `x16` 物理插槽在电气上往往只布线了 `x8` 或 `x4`（常接在芯片组 PCH 下）。

### 2. 合法的动态降宽节能
部分设备支持 **Hardware Autonomous Width**（硬件自主调宽），在系统低负载时主动关闭部分 Lane 省电，高负载时再恢复全宽（可通过 `Link Control` 寄存器的 Bit 6 禁用）。

### 3. Linux 下快速排查降宽问题

```bash
# 对比设备硬件上限 (LnkCap) 与当前协商宽度 (LnkSta)
sudo lspci -vv -s 01:00.0 | grep -E "LnkCap:|LnkSta:"
# 也可直接读取 sysfs 节点：
cat /sys/bus/pci/devices/0000:01:00.0/max_link_width
cat /sys/bus/pci/devices/0000:01:00.0/current_link_width
```

如果 `LnkCap` 显示 `Width x16` 而 `LnkSta` 显示 `Width x4 (downgraded)`，应优先检查物理插槽布线规格、重新插拔设备或排查 BIOS 中的通道拆分设置。

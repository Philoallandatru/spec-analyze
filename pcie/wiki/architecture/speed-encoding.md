# PCIe 速率与编码

**一句话总结**：PCIe 每一代带宽翻倍不仅依靠提高物理信号速率（`GT/s`），更依靠不断升级**编码方案**（从 8b/10b 到 128b/130b 再到 PAM4 Flit），在尽量降低额外开销的同时保证高速信号可被可靠解码。

> **直观类比**：如果把物理链路比作卡车运货，`GT/s` 是卡车每秒发车的趟数，而**编码效率**就是每辆卡车里“真货物”占车厢的比例——早期车厢要用 20% 空间放防撞泡沫（8b/10b），后来技术进步只需要 1.5% 泡沫（128b/130b），净运力瞬间大增。

## PCIe 各代速率与编码演进

| 代际 | 原始速率 (每 Lane) | 调制与编码方案 | 编码效率 | 单向有效带宽 (x1) | 单向有效带宽 (x16) |
|------|-------------------|---------------|---------|-------------------|-------------------|
| **Gen 1** | 2.5 GT/s | NRZ + 8b/10b | 80.0% | ~250 MB/s | ~4.0 GB/s |
| **Gen 2** | 5.0 GT/s | NRZ + 8b/10b | 80.0% | ~500 MB/s | ~8.0 GB/s |
| **Gen 3** | 8.0 GT/s | NRZ + 128b/130b | 98.5% | ~985 MB/s | ~15.75 GB/s |
| **Gen 4** | 16.0 GT/s | NRZ + 128b/130b | 98.5% | ~1.97 GB/s | ~31.5 GB/s |
| **Gen 5** | 32.0 GT/s | NRZ + 128b/130b | 98.5% | ~3.94 GB/s | ~63.0 GB/s |
| **Gen 6** | 64.0 GT/s | **PAM4** + 242B/256B Flit | 94.5% | ~7.56 GB/s | ~121.0 GB/s |

## 三代编码方案深度对比

### 1. 8b/10b 编码（Gen 1 / Gen 2）
- **工作原理**：将每 8 位数据映射为 10 位物理符号，额外多出的 2 位专门用来保证线路上 `0` 和 `1` 的数量长期均衡（**直流平衡，DC Balance**），且不会出现一长串连续相同的比特，方便接收端 **CDR（时钟数据恢复）** 提取时钟。此外还提供专门的控制字符（如 `K28.5` COM、`STP`、`END`）。
- **代价**：20% 的带宽直接消耗在编码上。

### 2. 128b/130b 编码（Gen 3 / Gen 4 / Gen 5）
- **工作原理**：抛弃 8b/10b 的 20% 高昂开销，改为每 128 位净荷前只加 **2 位同步头（Sync Header）**：
  - `10b`：表示后续 128 位为数据块（TLP/DLLP）；
  - `01b`：表示后续 128 位为物理层有序集块（Ordered Set）。
- **如何保证时钟恢复与直流平衡？**：在编码前先通过 **加扰器（Scrambler）** 将数据与伪随机序列异或打散，从统计上保证充足的电平跳变。编码开销骤降至 `2/130 ≈ 1.54%`，效率高达 **98.5%**。

### 3. PAM4 与 242B/256B Flit（Gen 6）
当单通道速率推高到 64 GT/s 时，传统 **NRZ（非归零码，用高低 2 个电平表示 1 比特）** 的物理频率过高、PCB 损耗极大。PCIe 6.0 做出两项根本性变革：
- **PAM4（4 电平脉冲幅度调制）**：用 4 个电压等级在每个符号周期同时携带 **2 比特**信息（`00/01/10/11`），从而在不倍增模拟带宽的前提下实现 64 GT/s（等效 8.0 GB/s 原始速率/Lane）。
- **固定 256 字节 Flit（流控单元）与 FEC**：PAM4 抗噪能力天然弱于 NRZ，因此 Gen6 放弃变长帧，改用固定 256 字节 Flit 封装（236B TLP + 6B DLP 链路负载 + 8B CRC + **6B FEC 前向纠错**），有效负载占比 `242/256 ≈ 94.5%`，实现低延迟纠错。

## 带宽计算公式：理论值 vs 实测值

### 1. 链路层理论有效带宽
$$\text{理论有效带宽 (GB/s)} = \frac{\text{GT/s} \times \text{Lane数} \times \text{编码效率}}{8}$$

- 示例（Gen4 x4 NVMe SSD）：`16.0 × 4 × (128/130) / 8 ≈ 7.88 GB/s`
- 示例（Gen6 x16 加速卡）：`64.0 × 16 × (242/256) / 8 ≈ 121.0 GB/s`

### 2. 应用层实测吞吐量
在实际跑 `fio` 或 DMA 压测时，还要扣除 **TLP 包头（12–16B）、LCRC/序列号（6B）、Ack/Nak 与流控 DLLP 以及 SKP 有序集**等协议开销（约占 8%–12%）。因此：
- Gen3 x4 理论 3.94 GB/s，实测上限通常在 **~3.5 GB/s**；
- Gen4 x4 理论 7.88 GB/s，实测上限通常在 **~7.0–7.4 GB/s**。

## 速度协商与向后兼容

PCIe 天生支持跨代混插（如 Gen4 显卡插在 Gen3 主板上，或 Gen3 SSD 插在 Gen5 主板上），协商规则如下：
1. **起始握手**：所有链路均从最低公共速率 **Gen1 (2.5 GT/s)** 开始训练，确保任何两代设备都能先“说上话”。
2. **能力通告**：双方通过 `TS1/TS2` 有序集交换各自 `Link Capabilities`（`Max Link Speed`）支持的最高速率。
3. **逐级升速**：进入 `Recovery` 状态重新训练并执行**信号均衡（Equalization，Gen3+ 必需）**，最终稳定在**双方共同支持的最高速率**。

在 Linux 中可用 `lspci` 快速检查当前速率是否达到设备标称上限（排查“降速”故障）：

```bash
# 对比 Link Capabilities (硬件上限) 与 Link Status (当前协商结果)
sudo lspci -vv -s 01:00.0 | grep -E "LnkCap:|LnkSta:"
# 若 LnkCap 为 16GT/s 而 LnkSta 仅显示 8GT/s (downgraded)，说明发生了降速
```

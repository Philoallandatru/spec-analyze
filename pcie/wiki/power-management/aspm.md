# ASPM（Active State Power Management，活动状态电源管理）

**ASPM（Active State Power Management）** 是 PCIe 链路层与物理层协同工作的**硬件自动节能机制**。如果把设备级电源管理（D0~D3）比作“下班后由管理员手动拉闸断电”，那么 ASPM 就像是走廊里的**“红外感应灯”**：设备明明还处于工作状态（D0），但只要硬件检测到链路上暂时没有 **TLP（事务层数据包）** 传输，就会在微秒级自动把链路切入不同深度的节能状态（`L0s`、`L1`、`L1.1`、`L1.2`），一旦有新数据要发又立刻自动唤醒，全程对应用软件透明。

---

## ASPM 与设备电源状态（D0~D3）的区别

| 对比维度 | ASPM（链路电源状态 `L0`~`L1.2`） | PCI-PM（设备电源状态 `D0`~`D3`） |
|---------|-------------------------------|--------------------------------|
| **控制主体** | **硬件自动触发**（OS 仅配置策略与使能） | **软件显式控制**（OS/驱动写 PMCSR 寄存器或通过 ACPI） |
| **设备状态前提** | 设备本身仍处于 **D0（全功能工作态）** | 设备整体进入休眠或断电（D1/D2/D3hot/D3cold） |
| **唤醒延迟** | 亚微秒 ~ 百微秒级 | 毫秒 ~ 百毫秒级 |
| **典型用途** | 运行间隙的动态省电（笔记本续航、数据中心降耗） | 系统待机（S3）、关机或设备彻底闲置卸载 |

## ASPM 链路状态体系与转换

```
                       空闲检测 / 协议协商
      ┌──────────────────────────────────────────────────┐
      │                                                  ▼
┌───────────┐  发 EIOS 关 TX   ┌───────────┐      ┌───────────────┐
│    L0     │ ───────────────▶ │    L0s    │      │      L1       │
│  (全速)   │ ◀─────────────── │  (浅待机)  │      │  (深度低功耗)  │
└───────────┘  发 FTS/EIEOS    └───────────┘      └───────┬───────┘
      ▲                                                   │ 进入 L1 子状态
      │             唤醒事件（EIEOS / CLKREQ# 拉低）       ▼
      └───────────────────────────────────────────┌───────────────┐
                                                  │  L1.1 / L1.2  │
                                                  │ (关闭 PLL/时钟) │
                                                  └───────────────┘
```

### 各状态核心机制解析

1. **L0（Active，活动态）**
   - 链路全速运行，时钟与 **PLL（锁相环）** 全开，无传输延迟；空闲时发送 Idle 填充字符。
2. **L0s（Standby，浅待机态）**
   - **单向独立节能**：TX（发送端）与 RX（接收端）可各自独立进入 `L0s`，仅关闭发送器电路，保持接收器与参考时钟运行。
   - **进入**：发送 **EIOS（Electrical Idle Ordered Set，电气空闲有序集）** 后进入电气空闲。
   - **退出（< 1 μs，通常 200~500 ns）**：发送 **FTS（Fast Training Sequence，快速训练序列）**（Gen3+ 使用 **EIEOS**）让对端快速重新锁定时钟，立刻恢复 `L0`。
3. **L1（Low Power，低功耗态）**
   - **双向握手进入**：须链路两端均支持并启用 L1，由下游端口发起 `PM_Enter_L1` **DLLP（数据链路层数据包）** 握手确认后，双方同时进入电气空闲并关闭内部时钟分发（PLL 可选关闭）。
   - **退出（通常 2~4 μs）**：任一端发出唤醒信号（EIEOS），重新锁定 PLL 并经过简短链路训练回到 `L0`。
4. **L1.1 与 L1.2（L1 PM Substates，L1 子状态，PCIe 3.1+）**
   - **L1.1**：在 L1 基础上**彻底关闭 PLL**，但保留 100 MHz **REFCLK（参考时钟）**（恢复约 8~16 μs）。
   - **L1.2**：进一步通过 **CLKREQ#** 边带信号通知主板关闭 100 MHz 参考时钟，实现接近关机的超低功耗（恢复需 16~100 μs）。

### 功耗与延迟权衡对比

| 状态 | 典型功耗节省 | 典型退出延迟 | 适用场景建议 |
|-----|------------|------------|------------|
| **L0** | 0%（基准） | 0 | 持续高吞吐、超低延迟业务（如高频交易网卡） |
| **L0s** | ~10%–20% | 200–500 ns | 短暂间隙节能；对随机 I/O 影响极小（通常 < 5%） |
| **L1** | ~60%–90% | 2–4 μs | 笔记本/普通服务器平衡功耗与性能 |
| **L1.1** | ~90%–95% | 8–16 μs | 中长空闲期，保留参考时钟以兼顾恢复速度 |
| **L1.2** | ~95%–99% | 16–100 μs | 移动设备/轻载系统盘，配合 **LTR** 实现极致续航 |

> **什么是 LTR（Latency Tolerance Reporting）？**  
> 设备通过发送 LTR 报文主动向主板/RC 汇报自己“最多能忍受多久的唤醒延迟”。只有当设备当前声明的容忍延迟大于 `L1.2` 的退出阈值时，系统才允许链路进入 `L1.2`，从而防止高频业务被长唤醒延迟拖慢。

## 核心配置寄存器

ASPM 的基础开关位于标准 PCIe Capability（可通过 `lspci` 解析）的 **Link Capabilities (`+0x0C`)** 与 **Link Control (`+0x10`)** 中：

| 寄存器与位域 | 编码值与含义 |
|-------------|-------------|
| **Link Capabilities `[11:10]`**（ASPM Support） | `00b` = 不支持，`01b` = 仅 L0s，`10b` = 仅 L1，`11b` = 支持 L0s 和 L1 |
| **Link Capabilities `[14:12]` / `[17:15]`** | 分别声明设备离开 `L0s`（< 64 ns ~ > 4 μs）和 `L1`（< 1 μs ~ > 64 μs）的硬件退出延迟 |
| **Link Control `[1:0]`**（ASPM Control） | `00b` = 禁用，`01b` = 启用 L0s，`10b` = 启用 L1，`11b` = 同时启用 L0s 和 L1 |

> **生效原则**：一条链路能否进入 `L0s` 或 `L1`，取决于**链路两端（Upstream Port 与 Downstream Port）的共同能力**以及操作系统对两端 `Link Control` 的协同配置。

## Linux 查看与策略调优

```bash
# 1. 查看指定设备的 ASPM 硬件能力与当前启用状态
lspci -vvv -s 01:00.0 | grep -E "LnkCap:|LnkCtl:"

# 2. 查看并切换系统全局 ASPM 策略
cat /sys/module/pcie_aspm/parameters/policy
# 输出示例: [default] performance powersave powersupersave
#   performance    : 禁用 ASPM，追求最低延迟
#   powersave      : 启用基础 ASPM (L0s/L1)
#   powersupersave : 启用深度节能（含 L1.1/L1.2）
echo powersave > /sys/module/pcie_aspm/parameters/policy

# 3. 内核启动参数（当部分老旧硬件开启 ASPM 导致掉盘/卡顿时使用）
# pcie_aspm=off   (全局关闭)   |   pcie_aspm=force (强制无视 BIOS 禁用)
```

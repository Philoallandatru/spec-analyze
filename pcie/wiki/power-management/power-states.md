# PCIe 电源状态（D-States 与 L-States）

**PCIe 电源状态**由两套相互关联的状态体系构成：**设备电源状态（Device Power States，D0 ~ D3cold）** 和 **链路电源状态（Link Power States，L0 ~ L3）**。可以把设备比作一家“工厂”，把 PCIe 链路比作工厂门口的“高速路”：工厂正常开工（`D0`）时，高速路可以全速通行（`L0`），也可以在没货车时自动调暗路灯（`L0s`/`L1`）；而当工厂下班打烊（`D3hot`）甚至拉闸断电（`D3cold`）时，高速路也会同步封闭（`L1`/`L2`/`L3`）。

---

## 一、设备电源状态（D0 ~ D3cold）

设备电源状态由操作系统或驱动程序通过写入 PCI Power Management Capability（`Cap ID = 0x01`）中的 **PMCSR（Power Management Control/Status Register）** 或通过 **ACPI（高级配置与电源接口）** 控制：

| 设备状态 | 主电源 (`Vcc`) | 辅助电源 (`Vaux`) | 上下文与配置空间 | 核心特性 |
|---------|---------------|------------------|----------------|---------|
| **D0** | 开启 | 开启 | 完全保留 | 全功能正常工作状态（可细分为未初始化 `D0uninitialized` 与活动 `D0active`） |
| **D1 / D2** | 开启 | 开启 | 保留 | 介于 D0 与 D3 之间的可选中间省电态（大多数现代 PCIe 设备跳过这两级，仅用 D0 与 D3） |
| **D3hot** | 开启 | 开启 | **保留**（可访问配置空间） | 睡眠态：停止收发常规业务 TLP，链路进入 `L1`；可通过写 PMCSR 毫秒级快速唤醒回 `D0` |
| **D3cold** | **关闭** | 可选保留（`Vaux`） | **丢失** | 彻底断电态：主电源切除，仅靠 `Vaux` 维持唤醒电路（或全断）；唤醒需重新上电、重新训练链路并由 OS 恢复配置空间 |

---

## 二、链路电源状态（L0 ~ L3）

链路电源状态描述物理层与数据链路层的通信通道状态，与设备 D 状态存在严格的联动关系：

```
          ┌──────────────────────────────────────────┐
          │                 L0 (Active)              │ ◀── 全速通信（设备处于 D0）
          └──────┬──────────────────────────┬────────┘
                 │ 空闲 (ASPM)              │ 空闲 (ASPM) 或 软件置 D3hot
                 ▼                          ▼
          ┌─────────────┐            ┌─────────────┐
          │ L0s (待机)  │            │ L1 (低功耗) │ ◀── 可细分为 L1.0 / L1.1 / L1.2
          └─────────────┘            └──────┬──────┘
                                            │ 系统发 PM_Turn_Off 广播，准备断电
                                            ▼
                                     ┌─────────────┐
                                     │ L2 (辅助电) │ ◀── Vcc 关，Vaux 留，支持 PME 唤醒
                                     └──────┬──────┘
                                            │ 切断 Vaux
                                            ▼
                                     ┌─────────────┐
                                     │  L3 (全关)  │ ◀── 完全断电，恢复需重新枚举
                                     └─────────────┘
```

### 链路状态与唤醒机制对比

| 链路状态 | 对应设备状态 | 功耗 | 典型恢复延迟 | 唤醒机制 | 配置空间访问 |
|---------|------------|------|------------|---------|------------|
| **L0** | D0 | 100% | 0 | — | 允许 |
| **L0s** | D0（ASPM） | 60%–80% | < 1 μs | 发送 **FTS / EIEOS** 快速锁定 | 允许 |
| **L1**（含 L1.1/L1.2） | D0（ASPM）或 D3hot | 1%–20% | 2 ~ 100 μs | EIEOS + **CLKREQ#**（L1.2）+ 链路重训练 | D0 下允许；D3hot 下仅允许有限访问 |
| **L2** | D3cold（有 `Vaux`） | < 1% | > 50 ms | 靠 `Vaux` 供电发出 **WAKE#** 边带信号或 **Beacon**，触发上电与完整训练 | 禁止（需先恢复供电） |
| **L3** | D3cold（无 `Vaux`） | 0% | > 100 ms | 无法自主唤醒，需系统重启或重新供电枚举 | 禁止 |

## 三、深度睡眠（L2/L3）的进入与唤醒机制

与微秒级自动进出的 `L0s`/`L1` 不同，进入 `L2`/`L3`（通常对应操作系统的 **ACPI S3 睡眠** 或 **S4/S5 关机**）需要严格的带内协议握手：

1. **软件降级**：OS 先保存设备配置空间，并将设备置于 `D3hot`。
2. **PM_Turn_Off 广播**：Root Complex 向下游广播 **PM_Turn_Off Message TLP**；所有下游设备收到后停止发包并回复 **PM_Ack**，随后链路进入 `L2/L3 Ready` 状态。
3. **切断主电源 (`Vcc`)**：主板确认所有端口进入准备状态后，拉低 `PERST#` 复位信号并切断主电源 `Vcc`。若保留 `Vaux` 辅助电源，则进入 **L2**；若连 `Vaux` 也切断，则进入 **L3**。
4. **远程唤醒（PME# / WAKE#）**：当处于 `D3hot/L1` 或 `D3cold/L2` 的网卡收到 Wake-on-LAN 魔法包时：
   - 在 `L1` 下：设备通过带内发送 **PM_PME Message TLP** 唤醒 Root Complex；
   - 在 `L2` 下（主链路已断电）：设备拉低专用的 **WAKE#** 边带引脚，通知主板恢复 `Vcc` 供电并重新训练链路。

## Linux 查看与调试接口

```bash
# 1. 查看设备当前 D 状态与 D3cold 允许策略
cat /sys/bus/pci/devices/0000:01:00.0/power_state
cat /sys/bus/pci/devices/0000:01:00.0/d3cold_allowed

# 2. 查看运行时电源管理（Runtime PM）状态：auto（允许自动进 D3）或 on（保持 D0）
cat /sys/bus/pci/devices/0000:01:00.0/power/control

# 3. 使用 lspci 查看 PCI Power Management Capability (PMCap / PMCSR)
lspci -vvv -s 01:00.0 | grep -A 3 "Power Management"
```

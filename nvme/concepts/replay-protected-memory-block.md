# 重放保护内存块（Replay Protected Memory Block, RPMB）

RPMB 是 NVMe 控制器中**独立于任何命名空间（Namespace）**的抗篡改安全存储区域（`128 KiB` 到 `32 MiB`，可被子系统内多个控制器共享）。它通过为每个目标（Target）配置不可读的密钥、**HMAC-SHA256** 消息认证码、**Nonce**（防重放随机数）和**单调递增写计数器**（防回滚），使主机无需暴露密钥即可完成已认证的数据读写；其中 **Target 0** 还包含一个 512 字节的设备配置块（DCB），用于控制引导分区（Boot Partition）和命名空间的写保护。[PDF pp. 569-573](../_source/pages/page-569.md)

可以把 RPMB 想成**银行金库的凭证保险箱**：
- **RPMB Target** = 独立的保险箱，每个都有自己的唯一钥匙（一次性写入、不可读取的密钥）
- **MAC（HMAC-SHA256）** = 防伪签名，证明请求和响应确实来自持有密钥的合法双方
- **Nonce（随机数）** = 每次取款带的当次验证码，银行在回执里原样回填，防止攻击者拿旧回执重放
- **Write Counter（写计数器）** = 递增的存折流水号，每次成功写入加 1，防止攻击者把旧写请求重放回滚数据
- **DCB（Target 0 专属）** = 保险箱外的总控指示牌，决定引导分区和命名空间是否锁定写保护

## 安全模型与命令传输机制

RPMB 帧通过安全协议命令承载：**`Security Send`** 发送请求，**`Security Receive`** 取回响应，两者均须设置 `NSID = 0`，且协议字段 `SECP = EAh`、`SPSP = 0001h`、`NSSF = Target ID`。[PDF pp. 570, 573-574](../_source/pages/page-570.md)

```text
  [安全预置阶段] 在安全环境中写入 256 位密钥到目标（一次性写入，不可读/不可擦除）
        |
        v
  主机生成 RPMB 帧（256 字节前缀 + 可选数据）
  ┌──────┬──────┬────────┬───────┬─────────┬──────┬────────┬──────┬──────┐
  │ 填充 │ MAC  │ 目标ID │ Nonce │ 计数器  │ 地址 │ 扇区数 │ 结果 │ 类型 │ + 数据
  └──────┴──────┴────────┴───────┴─────────┴──────┴────────┴──────┴──────┘
                 |<----------- HMAC-SHA256 计算覆盖范围 ------------>|
        |
        +─> Security Send（携带请求） ─> 控制器校验 MAC / 计数器 / 地址
        |                                       |
        +─> [写操作需发 0005h 请求结果] <───────'
        |
        `─> Security Receive（取回响应，主机必须自行校验返回的 MAC 与 Nonce）
```

### 密钥与计数器规则
- **密钥一次性编程**：密钥写入本身未经认证，因此必须在产线等安全环境中完成。写入后不可读取、修改或擦除；未编程密钥前访问目标会返回"认证密钥尚未编程"错误。
- **32 位单调写计数器**：每次成功写入数据区后加 1，不可重置；达到饱和值 `FFFFFFFFh` 后无法继续写入，状态位报告计数器过期。读取操作不消耗计数器。
- **DCB 独立计数器**：Target 0 的 512 字节 DCB 拥有独立的写计数器，不与数据区共享。DCB 可控制永久启用引导分区保护（一旦启用无法关闭）以及命名空间断电前/永久写保护（写保护控制位在上电循环或控制器重置时清零）。

## 核心操作序列

| 操作类型 | 请求与响应序列 | 关键验证与说明 |
|----------|----------------|----------------|
| **密钥编程** | `Send 0001h`(密钥) → `Send 0005h`(结果请求) → `Receive 0100h`(结果) | 按目标独立编程，不可撤销 [PDF pp. 574-575](../_source/pages/page-574.md) |
| **读计数器** | `Send 0002h`(Nonce) → `Receive 0200h`(Nonce, 计数器, MAC) | 获取当前写计数器用于后续写操作 |
| **已认证写** | `Send 0003h`(计数器, 地址, 数据, MAC) → `Send 0005h`(结果请求) → `Receive 0300h`(结果, 新计数器, MAC) | 控制器依次校验计数器过期、地址、MAC、当前计数器；失败则数据与计数器均不变 [PDF pp. 575-577](../_source/pages/page-575.md) |
| **已认证读** | `Send 0004h`(Nonce, 地址, 扇区数) → `Receive 0400h`(Nonce, 数据, 结果, MAC) | 响应绑定主机 Nonce；**验证返回 MAC 是主机的责任** [PDF pp. 575-578](../_source/pages/page-575.md) |
| **DCB 写/读** | 写：`0006h` → `0005h` → `0600h`；读：`0007h` → `0700h` | **仅限 Target 0**，固定 512 字节块；不能禁用已启用的引导分区保护 [PDF pp. 578-580](../_source/pages/page-578.md) |

### 实践关键注意点
- **`Security Send` 成功 ≠ RPMB 操作成功**：`Security Send` 完成仅表示命令已被处理；主机**必须**再发送 `0005h` 结果请求并通过 `Security Receive` 取回并校验签名结果，才能确认写入成功。
- **常见错误分类**：认证失败、计数器错误、地址错误、写入失败、读取失败、密钥缺失、配置无效。
- **并发与交错**：不同 RPMB 目标的请求可交错执行；同一目标需要严格保序时，主机应等待上一个安全命令完成。

## 关联与引申概念

- **HMAC-SHA256**：基于共享密钥和 SHA-256 哈希的消息认证码算法，用于验证 RPMB 帧的完整性和来源真实性，防止总线篡改。
- **Security Send / Security Receive**：NVMe 提供的通用安全协议信封命令，除用于 `EAh` 协议的 RPMB 外，也承载 TCG Opal 等外部安全协议。
- **Boot Partition（引导分区）**：用于存放系统启动镜像的受保护存储区，由 RPMB Target 0 的 DCB 控制其写保护锁定状态。

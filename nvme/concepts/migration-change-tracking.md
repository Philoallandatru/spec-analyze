# 迁移变更追踪（Migration Change Tracking）

## 一句话说明

迁移变更追踪是一对 **Track Send / Track Receive** 命令，专门记录"控制器迁移过程中**发生了什么数据变化**"，把变化通过控制器数据队列（用户数据）或变更描述符（主机内存）暴露给管理控制器，让迁移能形成可确定的截止点。

## 生活化类比

把迁移变更追踪想成**搬家时的"物品变动清单"**：

- **搬家方案管理员 = Management Controller**，用 `Track Send` 下达"开始记录某房间变动"。
- **要搬家的房间 = Target Controller**（被观测的控制器）。
- **物品变动清单的两种格式**：
  - **格式 A（用户数据变更日志，`SEL=0h`）**：物品每一次挪动都按"哪个箱子、去了哪里"写一行，**发到指定的收件箱（CDQ）**。
  - **格式 B（主机内存变更追踪，`SEL=1h`）**：追踪搬运工**碰过哪片仓库地面**，**记到描述符（地址 + 长度）**里。
- **搬运工下班 = 目标控制器被 Suspended**：此时再发 `Track Receive`，当 `MTR=0 & SUSP=1` 时，**可以保证不会再有新变动**——清单"盖章封存"。

清单的"消费"是**破坏性读取**：读了之后，已报告的记录被清掉，留出空间给后续变更。

## 工作流程

```text
   Management Controller              Target Controller
          |                                  |
          |  Track Send (SEL, 参数)          |
          |--------------------------------->|
          |  SEL=0: 用户数据 -> CDQ          | 命令处理 + 写入主机内存
          |  SEL=1: 主机内存 -> 描述符        |
          |                                  |
          |<---------------------------------|
          |  状态: 追踪中                    |
          |                                  |
          |  Track Receive: 拉取变更          |
          |--------------------------------->|
          |                                  |
          |<----- 描述符 / CDQ 条目 --------|
          |  (MTR=1: 继续; MTR=0: 没了)      |
          |                                  |
          |  若 MTR=0 & SUSP=1 -> 截止点确立 |
          +----------------------------------+
```

简化说明：上图省略了具体的 CDQID/CNTLID/描述符协商细节。

### 两种追踪模式

| 模式 | `SEL` | 追踪的变更 | 记录方式 | 适用场景 |
|------|-------|-----------|----------|---------|
| 用户数据变更日志 | `0h` | 对目标控制器的命名空间用户数据修改 | 控制器向 CDQ 发条目，**条目格式由 I/O 命令集定义** | 追踪命名空间级别数据变更 |
| 主机内存变更追踪 | `1h` | 目标控制器对主机内存的写入 | 记录主机内存**地址范围** | 追踪控制器对主机内存的直接写入 |

### 启动/停止动作

- 用户数据模式：用 `LACT`（Logging Action）启动/停止；用 CDQID 标识队列。
- 主机内存模式：用 `TACT`（Tracking Action）启动/停止；用 CNTLID 标识目标。

## 初学者案例

**场景：要把控制器 A 的数据迁到控制器 B，迁移期间如何知道"改了哪些"？**

1. 管理控制器在 A 处于被观测位置时，发 `Track Send`：
   - `SEL=0h`、`LACT=1h`（Start Logging）、`CDQID=0`（选 A 上的某个控制器数据队列）。
2. 控制器校验：CDQ 存在、目标未挂起、还没有别的控制器在为同一目标记录——通过后**开始**记。
3. 期间任何对 A 命名空间的用户数据写入，**作为条目**写入 CDQ；条目格式由当前 I/O Command Set 规定。
4. 迁移进入收尾时，**先**把目标挂起（Suspend），**再**连续发 `Track Receive`：
   - 每次返回一批描述符/条目，**消费掉**。
   - 直到某次 `MTR=0 & SUSP=1`：所有已发生的变更都报告了，且**目标仍挂起**，不会有新变更。
5. 此时刻就是**确定的迁移截止点**，可以安全地切数据平面。
6. 停追踪：`Track Send` 的 `LACT=0h` / `TACT=0h`。

> 故障速查：拿到"还有变更"但 `MTR=0`：检查 `SUSP`——目标未挂起则 `MTR=0` 仅是"瞬时无更多变更"，**不构成截止点**。

## 必须记住的规则

| 规则 | 要点 |
|------|------|
| 命令对偶 | `Track Send`（发送追踪请求）+ `Track Receive`（拉取已追踪变更）配套使用 |
| 两种模式 | `SEL=0h` 用户数据；`SEL=1h` 主机内存；不可混淆 |
| 破坏性读取 | `Track Receive` 成功返回后，**已报告记录被消费** |
| 挂起才截止 | `MTR=0 & SUSP=1` 才是"已追踪变更全部报告完"的可靠信号 |
| 不能自追踪 | 处理追踪的控制器**不能追踪自己** |
| 不能追踪挂起目标 | 目标已 Suspended 时**不能**启动新的追踪 |
| 唯一性 | 子系统内**同时只能有一个控制器**在追踪某个目标 |
| 范围参数 | 主机内存追踪的参数：粒度、范围数量、范围长度限制均受 Identify Controller 报告的最小/最大值约束 |
| 描述符对齐 | 描述符的地址与长度必须**按粒度对齐** |
| 协商回退 | 资源不足时返回 Not Enough Resources 并提供实际可支持的粒度/数量 |
| 公平性 | 同一地址高频变更**可能被延迟报告**，以保证其他地址的变更也能被公平报告 |
| MSI 范围不要追踪 | 控制器报告 MSI/MSI-X 寄存器写入是**可选**的，不应请求追踪 |

## 容易混淆的地方

| 容易混 | 实际区别 |
|--------|----------|
| Track Send vs Track Receive | Send 配置追踪（启动/停止、参数）；Receive 拉取已发生变更 |
| `SEL=0h` vs `SEL=1h` | 一个走 CDQ（命名空间数据），一个走描述符（主机内存地址） |
| `LACT` vs `TACT` | `LACT` 用于用户数据日志模式；`TACT` 用于主机内存追踪模式 |
| `CDQID` vs `CNTLID` | `CDQID` 是本地控制器数据队列 ID；`CNTLID` 是被观测的**目标控制器 ID** |
| `MTR=0` vs 真正的截止点 | 只有当 `MTR=0 & SUSP=1` 时才是确定的迁移截止点 |
| 启动追踪 vs 停止追踪 | `LACT=1h` / `TACT=1h` 启动；`LACT=0h` / `TACT=0h` 停止（停止时数据缓冲区被忽略） |
| 用户数据模式 vs 自检日志 | 一个是迁移场景下的命名空间用户数据变更；一个是设备健康自检 |
| 描述符 vs CDQ 条目 | 描述符是地址+长度（主机内存）；CDQ 条目由 I/O Command Set 决定 |
| 已消费 vs 已记录 | "消费"只代表"已被 Read 报告过"，不代表"已迁移完成" |
| 资源不足 vs 参数非法 | "Not Enough Resources" 携带**实际可支持的参数**，参数非法仅是错误 |

## 进阶细节

- **Track Receive 响应字段**：
  - **Target Controller ID**：被观测的目标控制器标识。
  - **粒度**：本报告使用的报告粒度。
  - **描述符数量**：本批次返回的描述符个数。
  - **MTR（More To Report）= 1**：还有变更待收。
  - **SUSP=1**：目标在命令处理期间被挂起。
- **描述符字段（16 字节/项）**：
  - 起始地址：按报告粒度对齐。
  - 长度：以报告粒度为单位的变更长度。
  - 零描述符必须对应 `MTR=0`（表示"没有变更可报告"）。
- **请求描述符格式（12 字节/项）**：
  - 版本 0。
  - 1 基计数（1 表示第一个描述符）。
  - 每项 12 字节：起始地址（按页粒度对齐）+ 长度（页单位）。
  - 标识目标控制器通过 PRP/SGL 访问的主机内存地址。
- **参数协商机制**：粒度/数量不被接受时返回 `Not Enough Resources`，并附带实际能力；主机据此调整后重发。
- **内存重新配置的限制**：若已接受的追踪范围**后续被改出主机内存**区，**后续追踪行为未定义**——应避免此情况。
- **CDQ 日志条目格式由 I/O Command Set 规定**：基础规范不规定条目字段；NVM Command Set、Zoned Command Set 各自定义。
- **唯一性约束的实现**：子系统内同一目标同时只能由一个控制器追踪；新请求被拒。
- **公平性约束**：控制器为防止"同一热地址刷屏"可能延迟报告，保证**多地址**变更的可见性。
- **Suspend 边界语义**：Suspend 期间已下发的命令**可能**还在返回；变更追踪**只看"已确认写入"的部分**。
- **子命令粒度边界**：粒度 = `2^n × 4 KiB`，n 受 Identify Controller 报告的最小/最大限制。
- **Track Send 启动失败语义**：重复追踪同一目标、目标已挂起、CDQ 不存在等场景**统一**返回命令级错误。

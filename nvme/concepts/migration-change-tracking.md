# 迁移变更追踪（Migration Change Tracking）

**迁移变更追踪（Migration Change Tracking）**用于虚拟机热迁移、控制器故障切换或在线存储迁移期间，持续记录目标控制器发生的数据变更，以便管理控制器增量同步并在目标挂起（Suspend）时确立确定的数据截止点。它通过 **Track Send（发送配置）** 与 **Track Receive（拉取变更）** 这一对 Admin 命令协同实现。[PDF pp. 433-438](../_source/pages/page-433.md)

可以把这套机制想象成**搬家时的"物品变动清单"**：管理控制器通过 `Track Send` 下令"开始记录目标房间（目标控制器）的变动"——要么把每次命名空间写入记入专门的收件箱（控制器数据队列 CDQ），要么追踪目标控制器碰过哪些主机内存地址范围；搬家收尾时把目标房间"挂起"并不断用 `Track Receive` 取走清单，直到 `MTR=0` 且 `SUSP=1`，即可确认不会再有新变动。

## 交互模型与两种追踪模式

```text
管理控制器 (Management Controller)            目标/处理追踪的控制器
       |                                              |
       |  Track Send (SEL, 启动/停止, 追踪参数)        |
       |--------------------------------------------->|  处理命令 / 写入主机内存
       |<---------------------------------------------|  追踪状态就绪
       |                                              |
       |  Track Receive (拉取已追踪变更)               |
       |--------------------------------------------->|
       |<----- 变更描述符 / CDQ 条目 (破坏性消费) -----|
       |       (MTR=1: 还有更多; MTR=0: 暂空)         |
       |                                              |
       |  当 MTR=0 且 SUSP=1 -> 确定迁移截止点确立     |
```

| 追踪模式 | `SEL` | 追踪对象 | 启停字段与标识 | 记录方式 |
|---|---|---|---|---|
| **用户数据变更日志** | `0h` | 目标控制器对命名空间用户数据的修改 | `LACT` 启停；本地 `CDQID` 标识队列 | 控制器向 **CDQ（控制器数据队列）** 发布条目，条目格式由具体 I/O 命令集定义 |
| **主机内存变更追踪** | `1h` | 目标控制器对主机内存的直接写入 | `TACT` 启停；`CNTLID` 标识目标控制器 | 控制器记录对齐的主机内存地址范围变更描述符 |

## 主机内存追踪（`SEL=1h`）与用户数据日志（`SEL=0h`）规则

### 启动前提与限制

- **禁止自追踪与重复追踪**：处理追踪的控制器不能追踪自己；不能对已处于挂起（Suspended）状态的目标控制器启动追踪；同一时间子系统内**只能有一个控制器**追踪某个目标。[PDF pp. 436-438](../_source/pages/page-436.md)
- **停止追踪**：将 `LACT` 或 `TACT` 清零即可停止追踪（停止时数据缓冲区被忽略）。
- **CDQ 检查（`SEL=0h`）**：启动前检查指定的 `CDQID` 在当前控制器上是否存在、且无其他控制器正在为该队列关联的目标记录日志。[PDF pp. 436-437](../_source/pages/page-436.md)

### 请求描述符与资源协商（`SEL=1h`）

启动主机内存追踪时，管理控制器通过 12 字节请求描述符（版本 0，1 基计数）指定一个或多个由目标控制器通过 PRP/SGL 访问的主机内存范围：[PDF pp. 437-440](../_source/pages/page-437.md)

- **粒度与对齐**：粒度编码为 `2^n × 4 KiB`，必须在 Identify Controller 报告的最小/最大粒度范围内；每个范围的起始地址和长度（页单位）必须按粒度对齐（若启用 2 的幂长度限制，长度还须为 `2^k`）。
- **资源协商回退**：若控制器无法满足请求的粒度或描述符数量，返回 **`Not Enough Resources`** 并在响应中附带实际支持的粒度和数量，主机可据此调整参数重发。
- **特殊禁忌**：不应请求追踪 MSI/MSI-X 中断寄存器范围（控制器上报此类写入是可选的）；若已接受的追踪范围后续被重新配置为非主机内存，追踪行为未定义。[PDF pp. 439-440](../_source/pages/page-439.md)

## 变更接收（Track Receive）与截止点语义

Track Receive 固定选择 `Tracked Memory Changes`（使用 0 基 dword 计数），遵循**破坏性读取（Destructive Read）**语义：成功返回后，已报告的变更记录即被清除消费；为防止单个热地址刷屏，控制器可延迟报告高频变更以保证多地址公平性。[PDF pp. 433-434](../_source/pages/page-433.md)

| 响应字段 | 含义 |
|---|---|
| **响应头** | 包含 Target Controller ID、报告粒度、本次返回的描述符数量、`MTR`（More To Receive）与 `SUSP`（目标是否已挂起） |
| **变更描述符（16 字节/项）** | 按报告粒度对齐的起始地址 + 以报告粒度为单位的长度；0 个描述符必须对应 `MTR=0` |
| **`MTR=0` 且 `SUSP=1`** | **确定的迁移截止点**：目标控制器已挂起且所有已确认变更已全部报告，恢复前不会再产生新变更（若 `SUSP=0`，`MTR=0` 仅表示瞬时无积压） |

## 关联与引申概念

- **控制器迁移（Controller Migration）**：Migration Send/Receive 负责控制器自身状态迁移，并提供挂起（Suspend）原语使变更追踪收口。详见 [控制器迁移](controller-migration.md)。
- **控制器数据队列（CDQ / UDMQ）**：用户数据迁移队列（User Data Migration Queue, UDMQ）是 CDQ 的一种应用，用于在 `SEL=0h` 模式下向管理控制器推送命名空间写入记录。详见 [控制器数据队列](controller-data-queues.md)。
- **Identify 命令模型**：Identify Controller 披露主机内存追踪的最小/最大粒度、描述符数量上限以及 UDMQ/CDQ 上限。详见 [识别命令模型](identify-command-model.md)。
- **持久化事件日志**：用于辅助记录迁移期间的系统级事件审计。详见 [持久化事件日志](persistent-event-log.md)。

# 设备自检（Device Self-test）

## 一句话说明

设备自检是 NVMe 提供的"**让设备自己跑诊断**"的 Admin 命令：可以启动短测试、扩展测试、主机发起的刷新、厂商特定测试，也可以中止一个已经在跑的自检；结果落到设备自检日志（Log Page 06h）里。

## 生活化类比

把设备自检想成**给硬盘做体检**：

- **短测试** = 抽血化验，5 分钟出结果。
- **扩展测试** = 全面体检，可能要跑几十分钟。
- **主机发起的刷新** = 不体检，让设备重新加载/重建内部健康快照。
- **厂商特定测试** = 不同医院有自己的特色套餐。
- **中止命令** = 中途喊停。
- **NSID 字段** = 体检范围（"只查心血管 / 查左膝 / 全身扫一遍"）。

体检记录（自检日志）会保存**最近 20 次**结果，按时间倒序排在"档案柜"里，旧的自动往后挪。

## 工作流程

```text
   [无测试运行]
        |
        | 启动 短/扩展/刷新/厂商测试
        v
   [测试正在运行] <──── 中止命令(Fh) ────┐
        |                               |
        | 尝试启动新测试                 | 执行中止 -> 记录最新结果
        v                               | -> 清除当前状态 -> 成功
   拒绝: Device Self-test in Progress   |
        |                               |
        +───────────────────────────────┘
        |
        v
   完成/中止: 新结果 -> 槽位 1
             旧结果 -> 槽位 2..20
```

简化说明：上图重建了规范图 173 的标准行为，不含厂商特定分支。

### 自检范围（NSID 字段）

| `NSID` 取值 | 测试覆盖 |
|------|---------|
| `00000000h` | 仅控制器（不含任何命名空间） |
| `00000001h` ~ `FFFFFFFEh` | 单个有效且活跃的命名空间 |
| `FFFFFFFFh` | 当前所有已挂接且可访问的命名空间 |
| 主机发起的刷新 | **忽略 NSID**，作用于整个控制器 |

### 测试类型（STC 字段）

| `STC` | 含义 |
|------|------|
| `1h` | 短测试（Short test） |
| `2h` | 扩展测试（Extended test） |
| `3h` | 主机发起的刷新（Host-Initiated Refresh） |
| `Eh` | 厂商特定测试（CDW15 在此时才有意义） |
| `Fh` | 中止当前测试 |

### 作用域覆盖

通过 `SDSO`（Self-test Device Scope Override）决定"测试中"状态的可见范围：

- `SDSO=0`：测试状态仅在本地控制器可见。
- `SDSO=1`：测试状态在整个子系统（Subsystem）范围内可见。

## 初学者案例

**场景：怀疑 SSD 偶尔掉盘，想让它自检一下**

1. 主机在 Admin SQ 提交 `Device Self-test` 命令，`STC=1h`（短测试），`NSID=FFFFFFFFh`（全盘扫描）。
2. 控制器校验参数 → 写入自检日志的"当前操作"字段 → 启动自检 → 命令**成功完成**。
3. 主机轮询 `GetLogPage(LID=06h)`：
   - `DSTOS=1h`（短测试进行中）+ 完成百分比。
4. 自检结束：
   - 控制器先把新结果**插入槽位 1**，再把"当前操作"清零；保证主机任何时刻都能读到一致状态。
   - 主机再次读取日志，看到完整结果（成功 / 失败 / 失败段编号 / 失败 LBA 等）。
5. 如果中途想停：发 `STC=Fh`，控制器**有序中止**（终止操作 → 写结果 → 清状态 → 成功返回）。

> 故障速查：日志里 `DSTOS` 卡在 1h/2h 不动 = 测试**真的在跑**，不是设备无响应；如果再来一个 `STC=1h` 启动命令直接返回 `Device Self-test in Progress` = 行为正常，**不要重试**。

## 必须记住的规则

| 规则 | 要点 |
|------|------|
| 命令类型 | `Device Self-test` 是 Admin 命令，不是 I/O 命令 |
| 唯一运行 | 同时只能有**一个**自检操作在跑；新启动命令在已有测试运行时被拒 |
| 范围选择 | `NSID` 选范围：单 NS / 全 NS / 控制器级；`STC=3h` 忽略 NSID |
| 原子更新 | 控制器**先写结果条目，再清当前操作字段**，保证主机看到完整状态转换 |
| 中止是良性的 | 中止不修改日志当前操作（无测试时），运行时中止会产生"已中止"结果条目 |
| 槽位管理 | 结果条目**最多 20 条**，按时间倒序；未用条目 `STC=Fh`、其他字段清零 |
| 作用域可跨控制器 | `SDSO=1` 时自检状态对子系统内其他控制器也可见 |
| 厂商特定语义 | `STC=Eh` 时 CDW15 才有意义，行为由厂商决定 |

## 容易混淆的地方

| 容易混 | 实际区别 |
|--------|----------|
| 自检 vs Sanitize | 自检是"体检，看哪里坏"；Sanitize 是"彻底擦除/复位" |
| 启动 vs 刷新 | `STC=1h/2h` 启动真正的测试；`STC=3h` 是刷新健康快照，**不会测硬件** |
| `DSTOS=0h` vs "没结果" | `0h` 表示**没有测试在跑**，不是"没结果"——结果在槽位 1..20 里 |
| `NSID=0` vs `FFFFFFFFh` | 都是"全系统/控制器"语义，但语义粒度不同：前者包含控制器自身，后者是"全命名空间"，Host-Initiated Refresh 直接忽略 |
| 短测试 vs 扩展测试 | 时长与覆盖深度不同；短测试**不能**替代扩展测试 |
| 中止 vs 启动 | `STC=Fh` 是中止；其他值是启动；空跑时发中止会**无操作成功返回** |
| 厂商特定测试 vs 厂商数据 | `STC=Eh` 走厂商流程；结果条目里的"厂商数据"字段是普通测试也能带的 |
| 失败 LBA 语义 | `FLBA` 是 I/O Command Set 专属的，由各命令集规范解释 |

## 进阶细节

- **命令双字 15（CDW15）的生效条件**：仅在 `STC=Eh`（厂商特定测试）时有意义，其他情况下为保留。
- **结果条目（28 字节）字段**：
  - Self-test Code（测试类型）
  - Self-test Result（成功/显式中止/复位/NSID 移除/格式化/执行失败/段失败/未知中止/清理操作）
  - Power On Hours（完成或中止时的运行时长，不计低功耗）
  - NSID + Failing LBA（仅 NSID Valid=1 时有效）
  - Status Code Type + Status Code（仅在独立标记为有效时保留）
  - Failing Segment（仅对特定结果类型有效，标识第一个失败段）
  - 厂商数据（实现定义，不改变基础规范的有效性规则）
- **基础规范定义的"当前操作"取值**：`none`、`short`、`extended`；其他值由厂商扩展。
- **完成百分比的可用条件**：仅在测试**活跃**时有意义；非活跃时为保留。
- **结果与状态顺序契约**：测试完成或中止时必须**先创建结果条目，再清 `DSTOS=0h`**，避免"状态清空但结果未写入"造成观察不到的事件。
- **作用域设置位置**：`SDSO` 来自 Identify Controller 数据结构里的 Device Self-test Options（DSTO）。
- **无关日志**：
  - 自检**不会**写入 SMART/Health 计数，但可以由主机读取。
  - 自检期间**不直接触发**异步事件；自检异常**可以**走 Error Information 日志。
- **生命周期联动**：
  - 若 Format NVM 正在进行，部分结果可能被规范化为 `NSID Removed`。
  - 复位可能让当前自检转写为"复位中止"结果。

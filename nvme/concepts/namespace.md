# 命名空间（Namespace）

## 一句话说明

命名空间是 NVMe 中"主机可寻址的逻辑卷"：从 NVM 存储资源中按容量划出一段、格式化为逻辑块，分配后挂载到一个或多个 I/O 控制器上，主机通过控制器访问它。

## 生活化类比

把命名空间想成**写字楼里的可独立出租的办公区**：

- **整栋楼（SSD）** = NVM 子系统的物理资源
- **办公区（命名空间）** = 划出来的一段独立空间，可被一个或多个租户共用
- **租户（控制器）** = 真正使用空间的实体，多个租户可以共享同一办公区
- **门禁卡（挂载关系）** = 控制器"持卡"才能进，没卡就进不去

划线、装修、给租户发卡是**互相独立**的三件事——你完全可以划出办公区但不装修，也可以装修好但不发给任何租户。

## 工作流程

```text
  NVM 存储资源
       │
       │  1. 分配（Namespace Management）
       ▼
  已分配的命名空间（allocated, inactive）
       │
       │  2. 挂载到 I/O 控制器（Namespace Attachment）
       ▼
  控制器 A 上 active  ──┐
                        ├── 一个共享命名空间（多控制器可见）
  控制器 B 上 active  ──┘
       │
       │  3. 主机通过控制器发 I/O 命令
       ▼
  主机读写数据
```

简化说明：分配、挂载、可访问三者**互相独立**。分配是"圈地"，挂载是"装门"，可访问是"门和路都通"。三件事两两独立，理论上有 8 种组合（2³）。

## 初学者案例

**场景：为什么 `nvme list` 看不到 Namespace？**

1. SSD 插上后 `lspci` 能看到 NVMe 设备（PCIe Function 在）。
2. `nvme list` 报 "No devices"——控制器存在但命名空间列表为空。
3. 用 `nvme id-ctrl /dev/nvme0` 看 `nn`（Namespace Number 字段）：如果 `nn=0`，说明子系统还没分配任何命名空间。
4. 解决：用 `nvme create-ns /dev/nvme0 -s <容量> -c <容量> -f <格式>` 创建命名空间。
5. 接着 `nvme attach-ns /dev/nvme0 -n <NSID> -c <控制器 ID>` 挂载。
6. 再 `nvme list` 就能看到 `/dev/nvme0n1` 了。

> 排错口诀：**看到控制器不等于看到命名空间**；PCIe 链路通 ≠ 业务通。**lspci 在、`nvme list-ns` 为空**，八成是分配或挂载没做。

**另一个常见错误**：分配后忘记挂载，命名空间存在但控制器看不见，`Invalid Field in Command` 错误。

## 必须记住的规则

| 规则 | 要点 |
|------|------|
| 命名空间是逻辑卷 | 一段被格式化为逻辑块的存储空间 |
| 三个独立维度 | 分配（子系统） × 挂载（控制器） × 可访问（路径） 三者独立 |
| 私有 vs 共享 | 私有 = 同一时刻最多一个控制器挂载；共享 = 子系统内两+ 控制器并发挂载 |
| 命名空间绑定 I/O 命令集 | 创建时绑定，整个生命周期不变（参考 nvm-subsystem.md） |
| 命名空间可挂到多控制器 | 共享语义受各 I/O 命令集规则约束 |
| 控制器必须支持该命令集 | 命名空间只能挂载到支持且启用了对应 I/O 命令集的控制器 |
| I/O 控制器才能挂载 | 命名空间**只能**挂载到 I/O 控制器，Administrative 控制器不能挂 |
| 命名空间可动态创建删除 | 通过 Namespace Management / Attachment 命令；不需重启 |
| 写保护级别 | 无保护 / 写保护（可解除）/ 断电前保护（不可解除）/ 永久保护（不可解除） |
| 保护时数据持久化 | 进入"断电前保护"或"永久保护"前，必须把所有缓存与元数据刷到介质 |
| 写保护 Feature ID | 命名空间写保护特性 ID = `84h` |
| 编号上限 | 命名空间 ID（NSID）有效范围 `1h ~ NN`，`0h` 与 `NN+1 ~ FFFFFFFEh` 无效，`FFFFFFFFh` 为广播值 |
| 持久标识符 | 命名空间自身有 UUID（128-bit）/ NGUID（128-bit）/ EUI64（64-bit），跨会话稳定 |
| 队列无绑定 | 命名空间和 SQ 无固定绑定；任一 I/O SQ 可访问该控制器上所有已挂载命名空间 |

## 容易混淆的地方

| 容易混 | 实际区别 |
|--------|----------|
| 命名空间 vs 逻辑块 | 命名空间是整段逻辑卷；逻辑块（Logical Block）是最小读写单位（如 512B、4KB） |
| 命名空间 vs 分区 | 分区是 OS 层概念；命名空间是 NVMe 设备层概念，分区建在命名空间上 |
| 分配 vs 挂载 | 分配是子系统层动作；挂载是控制器层动作；一个已分配未必挂载 |
| 私有 vs 共享 | 私有同一时刻最多 1 个控制器挂载；共享 2+ 控制器并发挂载 |
| 共享 vs 分散（Dispersed） | 共享是同一子系统内多控制器；分散是跨多个子系统 |
| 多路径 I/O vs 共享 | 多路径 = 1 主机通过多条路径到 1 命名空间；共享 = 多主机经不同控制器到 1 命名空间 |
| NSID vs 持久 ID | NSID 是临时句柄（可能掉电变）；UUID/NGUID/EUI64 是持久身份 |
| 命名空间 vs 卷（Volume） | 命名空间是 NVMe 设备层；卷是文件系统层；1 命名空间可建多卷 |
| 命名空间 vs NVM Set | 命名空间是主机可见的逻辑卷；NVM Set 是底层容量池 |

## 进阶细节

- **三个独立维度的 8 种状态组合**（规范 2.3.3 / 4.2.1）：
  - ① 未分配：NVM 资源未圈出
  - ② 已分配未挂载：圈了地没装门
  - ③ 已分配已挂载可访问：正常使用
  - ④ 已分配已挂载但不可访问：网络/路径故障
  - ⑤–⑧：其余组合（涉及"未挂载 + 不可访问"等）
- **I/O 命令集绑定**（规范 2.3.2）：命名空间与 I/O 命令集的关联在创建时确定，整个生命周期固定。
- **多控制器访问同一共享命名空间**（规范 4.2.2 / Figure 20-21）：
  - 同一共享命名空间对每个能访问它的控制器，**NSID 必须相同**
  - Identify Namespace 返回的内容对每个控制器**完全一致**
  - 各控制器可并发操作；原子性以**接收命令的控制器**为单位，**不跨控制器保证**
  - 主机软件或应用负责跨控制器命令排序
- **多路径隔离**（规范 4.2.3）：独立端口的复位**只影响该端口上的控制器**，不影响其他控制器、共享命名空间或别的控制器正在进行的操作。
- **SR-IOV 视图**：每个 VF 是一个独立控制器，命名空间可跨 VF 共享——是共享访问模型的另一种实现。
- **Asymmetric Namespace Access (ANA)**（规范 8.1.14 / 4.2.3）：当子系统对不同控制器呈现不同访问特性时，可报告 ANA。状态包含 Optimized / Non-Optimized / Inaccessible / Persistent Loss / Change。
- **命名空间写保护 Feature**（规范 8.1.18 / Figure 322）：
  - Feature ID `84h`（Namespace Write Protection）
  - 四个保护级别见 8.1.18 详细规则
  - 进入"断电前保护"或"永久保护"前，**所有缓存数据 + 元数据必须先刷到介质**，确保保护生效后无数据悬空
- **持久身份标识符的优先级**（规范 4.2.5）：主机软件应优先 UUID → NGUID → EUI64；可用 `UIDREUSE` 字段判断 NGUID/EUI64 的重用特性。
- **NSID 在多控制器环境中的一致性**（规范 4.2.1.4）：
  - 若子系统支持 Namespace Management / ANA Reporting / NVM Sets 中任一，**同一 NSID 在所有控制器上指向同一物理命名空间**
  - 否则私有命名空间 NSID 可能不唯一
- **静态 vs 动态控制器对命名空间的影响**（规范 3.1.2）：动态控制器下，**同一 NVM 子系统端口**访问的所有动态控制器初始挂载的命名空间集合相同；不同端口可有不同。

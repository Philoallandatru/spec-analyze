# 命名空间拓扑与变更日志（Namespace Topology and Change Logs）

## 一句话说明

NVMe 通过四类日志页（17h 分散参与者 / 1Ah 可达性组 / 1Bh 可达性关联 / 1Ch 已分配命名空间变更列表）让主机看见命名空间在子系统间与子系统内的拓扑关系，以及最近的变更事件。

## 生活化类比

把命名空间想成一栋**连锁公寓的某一间房**：

- **分散参与者列表（17h）** = 这间房在哪些城市的分店有副本（每家分店一个 NQN）。
- **可达性组（1Ah）** = 同楼层的房间集合（共享相同电梯 / 通道属性），告诉你"这间房在几楼、邻居是谁"。
- **可达性关联（1Bh）** = 楼层之间的合作关系（如支持快速拷贝 / 不支持快速拷贝）。
- **已分配命名空间变更列表（1Ch）** = 房管处的"最近一次盘点记录"——从上次看房到现在，有哪些房间被改了。

主机在拿到一份"快照"前，要看**版本号**（全局变更计数）对不对；对不上说明中间有人改过，要重新读。

## 工作流程

```text
  命名空间（NSID = N）的拓扑视图
  ┌──────────────────────────────────────────┐
  │  分散参与者（17h）                        │
  │   ├─ 子系统 1 NQN  (256 字节)             │
  │   ├─ 子系统 2 NQN  (256 字节)             │
  │   └─ ...                                  │
  ├──────────────────────────────────────────┤
  │  可达性组（1Ah）                          │
  │   └─ Group X: NSID 列表（升序，可选 RGO）  │
  ├──────────────────────────────────────────┤
  │  可达性关联（1Bh）                        │
  │   └─ Association Y: RGID 列表（升序，RAO）│
  └──────────────────────────────────────────┘

  变更追踪（1Ch）:
   正常:  [NSID a][NSID b]...[NSID n]   (≤1024)
   溢出:  [FFFFFFFFh][0][0]...[0]       → 主机必须全量重扫
```

简化说明：每类日志都有**头部**（含全局变更计数）+ **条目**（按类型组织）。分段读时主机**重读头部**对比计数，匹配才接受快照。

## 初学者案例

**场景：主机想知道一个分散命名空间"分到哪几个子系统"了**

1. 主机向控制器发 `Get Log Page (LID=17h, NSID=N)`，请求该命名空间的分散参与者列表。
2. 返回：头部 + N 个 256 字节的子系统 NQN 记录。
3. 主机用 NQN 发起跨子系统的连接 / 同步。
4. 想确认快照是否过期：看头部的全局变更计数（Generation Counter）；CLR 后从 0 递增；变了一定要重读。

**反例**：直接信任一份缓存下来的参与者列表——子系统动态增删时，你会访问已经不存在的副本。

> 速记：**计数不变再信任，计数变了重读**。

## 必须记住的规则

| 规则 | 要点 |
|------|------|
| 四类日志 | 17h 分散参与者 / 1Ah 可达性组 / 1Bh 可达性关联 / 1Ch 已分配命名空间变更列表 |
| 17h 限制 | NSID 不能为 `0h` 或 `FFFFFFFFh`；目标命名空间必须标记为分散式 |
| 17h 顺序 | 索引 0 固定是"处理该命令的控制器所属子系统" |
| 1Ah 范围 | 仅包含连接到当前控制器的命名空间所属组；NSID 升序 |
| 1Bh 范围 | 仅包含满足条件的可达性组所参与的关联；RGID 升序 |
| 1Ch 上限 | 单次最多 1024 个 NSID |
| 1Ch 溢出 | 超过 1024 → 首条 `FFFFFFFFh`，其余填 0；主机必须全量重扫 |
| RGO | Reachability Group Omit = 1 时 1Ah 描述符不返回 NSID 列表 |
| RAO | Reachability Association Omit = 1 时 1Bh 描述符不返回 RGID 列表 |
| 索引偏移 | 索引 0 = 头部；1、2、3... = 后续描述符 |
| 全局变更计数 | CLR 后从 0 递增；达上限回绕到 0 |
| 组级变更计数（可选） | 1 开始递增；绕回 1；为 0 表示**不报告**，主机须直接比对内容 |
| 快照一致性 | 分段读后主机重读头部；全局变更计数仍匹配才接受 |
| 关联特征值 01h | 基本可达性：可互访但不保证性能 |
| 关联特征值 02h | 不支持快速复制（Fast Copy） |
| 关联特征值 03h | 支持快速复制 |
| 1Ch 涵盖事件 | Identify 变化 / Attach / Detach / Create / Delete |
| 主机协调不在范围 | 主机如何发现远程参与者不在 NVMe 规范范围（一般用 NVMe-oF Discovery） |

## 容易混淆的地方

| 容易混 | 实际区别 |
|--------|----------|
| 17h vs 1Ah | 17h 列"哪些子系统有这份分散命名空间"；1Ah 列"本子系统内哪些命名空间同组" |
| 1Ah vs 1Bh | 1Ah 是"组内成员"；1Bh 是"组与组之间的合作关系" |
| 1Ch vs Changed Namespace List (05h) | 1Ch 是**已分配命名空间**的变更（子系统级）；05h 是**已挂载命名空间**的变更（控制器级） |
| 关联特征 01h vs 03h | 01h = 可互访但无性能保证；03h = 可互访且支持快速复制 |
| 关联特征 02h vs 03h | 02h = 明确**不支持**快速复制；03h = 明确**支持** |
| 全局 vs 组级变更计数 | 全局是子系统级；组级是单组级；后者可选，可为 0 |
| 计数为 0 vs 计数为 1 | 计数为 0 表示**不报告**；1 是有效起始值 |
| RGO=1 vs 缺 NSID | RGO=1 是控制器主动省略；缺 NSID 可能是配置问题 |
| 溢出标记 vs 有效广播 | 1Ch 溢出 `FFFFFFFFh` 是"重扫哨兵"；NSID 广播值也是 `FFFFFFFFh`——位置不同 |
| 主机发现 vs 子系统拓扑 | 主机如何发现远程参与者**不在规范范围**；拓扑是子系统内的可见性 |

## 进阶细节

- **分散参与者日志（17h）**（规范 5.2.12.1.17 / Figure 270）：
  - 索引 0 = 处理命令的控制器所属子系统（SUBNQN 字段匹配）
  - 每个参与者占 256 字节
  - 不接受的 NSID：`0h`（"所有命名空间"）和 `FFFFFFFFh`（保留）
  - 目标命名空间必须标记为分散式
  - Generation Counter：参与者增删时递增
  - 主机发现远程参与者的方法**不在 NVMe 规范范围**（通常用 NVMe-oF Discovery）
- **可达性组日志（1Ah）**（规范 5.2.12.1.18 / Figure 274-276）：
  - 仅含连接到当前控制器的命名空间所属的组
  - NSID 按升序
  - 分段读快照协议：主机重读头部，全局变更计数不同则重试
  - `RGO=1` 时描述符不含 NSID 列表
- **可达性关联日志（1Bh）**（规范 5.2.12.1.19 / Figure 277-278）：
  - 仅含满足条件的可达性组所参与的关联
  - RGID 按升序
  - 使用与 1Ah 相同的头部校验协议
  - `RAO=1` 时描述符不含 RGID 列表
- **已分配命名空间变更列表（1Ch）**（规范 5.2.12.1.20 / Figure 279）：
  - 最多 1024 个发生变更的 NSID
  - 溢出时首条 = `FFFFFFFFh`，其余 = 0
  - 涵盖：Identify 变化、Attach、Detach、Create、Delete
- **变更计数器的回绕行为**（规范 5.2.12）：
  - 全局变更计数：CLR 后从 0 递增，**回绕到 0**
  - 组级变更计数（可选）：从 1 递增，**回绕到 1**
  - 组级 = 0 表示**不报告**该计数；主机必须直接比较描述符内容
- **关联特征字段**（规范 5.2.12.1.19 / Figure 277）：
  - `01h` = 基本可达性：命名空间间可互访，**不保证性能特征**
  - `02h` = 不支持快速复制
  - `03h` = 支持快速复制
- **索引偏移协议**（规范 5.2.12）：当控制器支持 Index Offset 字段时，索引 0 = 头部，索引 1、2、3... = 后续描述符。
- **快照一致性算法**（规范 5.2.12）：主机分段读时记录全局变更计数；读完后**重读头部**比较计数；相同才接受该快照，不同则重试。
- **1Ch 与 05h 的差异**：
  - 1Ch（Log Page 1Ch）：子系统级，报告**已分配命名空间**的变更
  - 05h（Log Page 05h）：控制器级，报告**已挂载命名空间**的变更
  - 主机应**两个都监听**才能拼出完整视图
